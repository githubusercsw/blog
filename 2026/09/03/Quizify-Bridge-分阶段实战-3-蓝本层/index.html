Quizify Bridge 分阶段实战（三）：M3 蓝本层——yuanbao2anki 权威规则的 Kotlin 移植

Quizify Bridge 分阶段实战（三）：M3 蓝本层——yuanbao2anki 权威规则的 Kotlin 移植

日期：2026-09-03 · 系列第三篇

摘要

补全层修好了输入，接下来要回答”结构怎么定”——答案来自蓝本：yuanbao2anki 的 markdown.js。M3 的核心是把这套经过实战检验的权威规则逐行移植成 Kotlin，并保留它的”语法红线”（静默退化陷阱的硬性校验）。本文讲移植方法、关键规则、以及”直通蓝本”与”增强层”的边界。

1. 蓝本是什么

yuanbao2anki 是 AnkiDroid 生态里把 AI 对话转成 Quizify 卡片的成熟方案，其 markdown.js 实现了从 Markdown 到 Quizify 语法的完整转换。我们的项目叫 Bridge（桥），蓝本 = 桥的”设计图纸”。

但注意：蓝本的能力边界是网页 DOM。上一讲已说明，纯文本剪贴板输入需要补全层先修符号，蓝本才能发挥权威性。

3. 语法红线（RedlineChecker）：静默退化陷阱的硬校验

Quizify 语法有个反直觉特性：语法错误不报错，而是静默退化——折叠变纯文本、tabs 错乱、alert 漏内容。用户渲染出”错卡”而不自知。

RedlineChecker 就是这道防线，检查规则包括：

规则 检查内容 严重性
R1 :::: 与 === 同行混用 致命
R2 recite 块缺 %% 致命
R3 折叠开闭不平衡（LIFO 配对） 致命
R5 reveal 跨行 / 括号不配对 致命
T 系列 静默退化提示 需修

实现上分两类：折叠平衡（开闭计数 + LIFO 校验）与行内配对（reveal/fitb 括号、recite 百分号）。

4. 移植中的关键坑

4.1 ::: 与围栏的字面量冲突

代码示例里出现 ::: 字面量（如展示语法本身），旧实现 contains(":::") 会全文误判，导致整个文档跳过转换。修复：围栏感知扫描——只有围栏外的 ::: 才算结构标记。

4.2 嵌套折叠的 LIFO 闭合

Quizify 折叠 ::: 是 LIFO（后进先出）配对。蓝本处理 h1→h2 嵌套时，闭合顺序必须严格逆序，否则结构错乱。这个”LIFO 闭合 + 嵌套 ≤2 层”约束贯穿后续 M5.3 的路由设计。

5. 验证与产出

  • 蓝本 11/11 + 提取稿 216 行逐条断言全绿
  • RedlineChecker 对未闭合围栏反例实测拦截
  • 蓝本行为与增强层边界清晰化（蓝本权威 + 增强扩展）

6. 本阶段启示

“权威规则”不等于”复制代码”——移植过程中最花时间的不是翻译语法，而是理解每个规则背后的假设（输入是 DOM、h3 不折叠、列表转 NOTE…），并用测试把这些假设固化。假设不固化，下一轮迭代就漂移。
