Quizify Bridge 分阶段实战（七）：标题识别规则体系 P0-P3——从强信号到揭示语法

Quizify Bridge 分阶段实战（七）：标题识别规则体系 P0-P3——从强信号到揭示语法

日期：2026-09-03 · 系列第七篇

摘要

剪贴板文本没有 # 标题标记，折叠又从哪来？答案：从文本形态推断标题。这是全项目最有技术含量的一章——用规则体系把”AI 长文里的标题”从正文中识别出来，精度逼近人工标注（显式信号 ~90%）。本文完整拆解 StructureInference v2 的规则体系：强信号、弱信号揭示语法、长度策略、以及八类正文误判排除。

1. 问题：无标记文本怎么找标题

AI 平台复制出的文本没有 Markdown 标记，标题和正文都是裸文本：

要折叠，必须先回答：哪一行是标题？

2. 信号分级：强信号 vs 弱信号

2.1 强信号（命中即折叠，无长度门禁）

有明确形态特征的标题，直接命中：

信号 模式 示例
序号标题 方案/步骤/方法…+序号 方案一：买域名
中文编号 一、/（一）/（二） 一、背景
章节号 §N §1 CONTEXT BUDGET
轮次标题 第X轮/章/节/阶段/部分/篇/步 第一步：理解需求
原则标题 原则N： 原则一：注意力优先
emoji 前缀 🎨/⚓/✅/❌/⚠️/❗… 🎨 建筑学迁移优势
加粗短行 xxx（≤30字） 核心结论
疑问式 含疑问词（什么/如何/为什么…） 我的疑问是什么

2.2 弱信号（纯文本短行 → 揭示语法）

无任何标记的短行（≤40 字），用”标题形态 vs 正文形态”判定。

3. 揭示语法：标题像什么，正文像什么

灵感来自语言学（主位-述位理论 + 中文标题正则研究，HoWToBench / CY-T 35-2001）。

3.1 标题形态（判为标题）

  • 疑问式短语：「我的疑问是什么」「怎么解决 HTTPS？」
  • 名词性收尾：「HCI 的职业发展路径」「给你的选择建议」
  • 4~14 字孤立名词短语：「Agent 协作红绿灯」

3.2 正文形态（判为正文，8 类排除）

# 形态 示例
1 句读收尾（。，；…含右引号） “记忆已固化。”
2 口语/体标记收尾（了/着/过/吗/呢/吧/的） 明白了 / 做完了
3 尾冒号引导行（先于疑问式排除） 两个主流技术选型：
4 连接词/转折词开头（但是/所以/如果…） 但是这样做不行
5 叙事主体开头（我们/大家/这些…） 我们要先理解
6 动词/介词引导（适合/通过/需要/指定了/提出了…40+） 指定了验证方法
7 枚举前缀（Tier/Level/Phase/Round）、阿拉伯列表、把字句、含连接符号 向量 + 知识图谱混合
8 定义句（：+斜杠枚举）、这/那+是/有/在判断句 四层记忆架构：工作 / 情景 / 语义 / 程序

3.3 判定顺序（关键）

两个顺序陷阱（样本实证）：

  1. 尾冒号必须先于疑问式：「两个主流技术选型：」含冒号是引导行，若疑问式先判定会误判
  2. 右引号必须在疑问式之后：「人机交互到底是什么：不只是”画界面”」含疑问词是标题，若右引号先排除会误杀

4. 长度策略：能制卡 > 标题完美

初始规则”超长标题直接拒绝”被用户纠正：

能制卡 > 某一个标题不完美——命中即折叠，超长只影响展示，不影响生成。

  • 弱信号软护栏 40 字（超过不判弱信号，但强信号不设限）
  • emoji 标题放宽到 60 字
  • 超长标题：截断展示而非拒绝写入

5. 上下文辅助规则

  • 前一行尾冒号 → 本行按列表项处理（引导行后的行为短行）
  • --- 分隔线后 → 一级章节（H1）
  • 前一行完整句收尾（句读） → 视作段落边界，允许后一短行为标题（样本 08 实证）

6. 与 LLM 的差距（诚实审计）

场景 规则侧 人工/LLM
显式信号（序号/emoji/加粗） ~90% ~100%
列表项 vs 标题（上下文引导） ~60% ~100%
隐式语义标题 ~50% ~95%
层级归位（嵌套） 无 ~100%

最大差距：列表项 vs 标题（需要上下文理解）、层级归位（需要全局结构感知）。收敛方向：两个 LLM 兜底接口（引导行/列表项复核 + 层级归位）。

7. 验证

  • BatchInferenceTest 27 项（含每类信号的命中 + 8 类排除的回归护栏）
  • 全量回归：engine 139 全绿
  • 样本批处理双轨对比（脚本 vs 语义）驱动规则迭代

8. 本阶段启示

规则系统的天花板是”形态特征”，LLM 的天花板是”语义理解”。规则的优势是确定性、零成本、可测试；LLM 的优势是上下文感知。成熟的方案不是二选一，而是规则为主 + LLM 兜底——规则覆盖高频显式场景，LLM 处理规则覆盖不了的上下文场景。
