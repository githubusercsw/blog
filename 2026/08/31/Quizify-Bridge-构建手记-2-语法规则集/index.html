Quizify Bridge 构建手记（二）：语法规则集 R0–R11/T1–T10

Quizify Bridge 构建手记（二）：语法规则集 R0–R11/T1–T10

日期：2026-08-31

摘要

上篇交代了缘起与路线图。本篇深入 B 阶段的核心产出：一套可机器校验的 Quizify Markdown 语法契约——R0–R11 规则与 T1–T10 静默退化陷阱。重点不是语法本身多复杂，而是”把规则写成单一权威、可被代码消费”。

1. 为什么需要规则集

Quizify Markdown 表达力强，但手写极易出错：一个未闭合的折叠、一个重复的字母选项，都会让整块功能静默退化成普通文本——不报错，但卡片废了。

我们的应对是：把语法从”写在散文里”升级为”写进契约里”。最终沉淀为：

  • R0–R11：结构/语义规则（折叠、标签页、警示框、完形、高亮、选择题、代码围栏闭合等）。
  • T1–T10：静默退化陷阱（T 表示退化，出现即功能丢失，必须拦截或警告）。

2. 规则分层示例

规则 类别 说明
R1 折叠 ::: 配平 开闭数量必须相等
R2 标签页 === 成对 裸 === 会误关标签页
R5 警示框 > [!TYPE] TYPE ∈ {NOTE,TIP,WARNING,CAUTION}
R8 选择题 ;;; 校验 选项字母唯一、答案∈选项
R11 代码围栏 ``` 必闭合 最后一行 ``` 不可缺
陷阱 后果
T3 标签页内裸 === → 提前关闭 + 后续变 <h1>
T9 引用块后紧跟结构标记 → 标记被吞入引用

3. 单源权威，而非多副本

初期我们犯了经典错误：语法知识散落在 5 个文件（syntax_guide、SKILL、prompt、audit、validator），改一条规则要同步 4 处。

正解：syntax_guide.md 作为唯一权威，校验器/生成器/提示词都从它派生。这也是后续”规则单一真源（L1）”的由来。

4. 真机渲染闭环

R1–R7 样本经真机（AnkiDroid）渲染零异常，GATE-B→C 解锁。但注意：渲染通过 ≠ 写入通过——这是后面审计埋下的伏笔。

下一篇：一次根因审计——从”硬编码症状”回到”验证闭环缺失”。
