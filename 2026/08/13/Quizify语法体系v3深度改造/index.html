Quizify 语法体系 v3 深度改造

博客二：Quizify 语法体系 v3 深度改造

日期：2026-08-13

摘要

本文记录了 Quizify Markdown 语法体系的 v3 改造全过程：从嵌套语法调研报告出发，建立”单源权威→分层消费”架构，沉淀 9 大静默退化陷阱（T1-T9），并通过状态机实现精准校验。核心亮点是 T9 陷阱的现场发现——由一张真实卡片的渲染瑕疵反推 Markdown 解析器行为。

1. 背景：为什么语法体系需要改造

初始状态：5 个文件各自维护一份语法知识，彼此重复、部分矛盾。

修改一个语法规则，最多需要同步 4 个位置。 这就是连锁反应的根因——不是语法复杂，是知识分散且重复。

2. 架构方案：单源权威 → 分层消费

3. 嵌套矩阵：17 种验证过的组合

基于真实解析器（marked 18.0.6）端到端测试：

外层 内层 结果
::: === 标签页 ✅ 官方未测，实测正常
::: > [!WARNING] ✅
> [!TYPE] :::（反向） ✅
=== ;;; 选择题 ✅
三层 :::>:::>=== ✅

结论：递归嵌套本身不受限制——每个 block 扩展在收尾时都对内部内容重新解析。

4. 九大静默退化陷阱（T1-T9）

“静默退化”指语法错误不报错，而是功能块退化为普通文本或布局错乱。

# 陷阱 后果
T1 无标题 ::: 整块退化纯文本
T2 未闭合折叠 折叠结构丢失
T3 标签页内裸 === 提前关闭标签页 + 后续变 <h1>
T4 [[ ]] 跨行 无交互
T5 选择题选项字母重复 整个选择题退化
T6 答案字母不在选项 选择题退化
T7 多字母答案重复 自动去重
T8 Alert 内缺 > 前缀 内容漏出 alert
T9 引用块后紧跟结构标记 结构标记被吞入引用块

5. T9 陷阱的现场发现（最有价值的案例）

用户报告：卡片中”第一层：你的仓库到底有什么”没有成为折叠标题，反而和上一行构成了一个批注。

根因分析：Markdown blockquote 的 lazy continuation 规则。

折叠标记被吞进引用块后变成普通文本，Quizify 解析器不再识别。

修复：

沉淀：T9 写入了 syntax_guide.md（规则9）、prompt_template.md（注意事项11）、card_validator.py（validate_blockquote_fold_conflict）。

6. 状态机校验的三次迭代

T3 校验是最容易做错的：标签页的”闭合行”和”陷阱裸行”在语法上完全一样（都是独立 ===），必须用上下文状态机区分。

迭代1：简单状态机 → 闭合行被吞，永远无法触发报错
迭代2：加 seen_any_group 门禁 → 折叠块内文本在首个标签页组前误报
迭代3：折叠边界重置逃出链条 → 通过

教训：语法校验器的复杂度不在正则，而在上下文追踪。

7. 四个生成模式

模式 适用 关键语法
A 平铺折叠 纯概念 ::: + Q/A
B 折叠+警告框 有陷阱 > [!WARNING]
C 折叠+标签页 多方案对比 ===
D 嵌套+自测 层级体系 2层 ::: + ;;;
